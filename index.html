抖音 GMV 异动分析 Agent

从“发现 GMV 下滑”到“给出可执行动作”的可解释诊断流程
合成面试样本：以下数据为模拟案例，展示 Agent 的分析过程与证据标准；不代表真实抖音店铺数据。
案例：夏季清仓专场 10:00–11:00 GMV 异动
基线：昨日同小时｜支付 GMV 口径｜数据截至 11:05

① Agent 接收的经营数据

颗粒度：小时 × 渠道 × 直播间 × SKU
数据新鲜度：5 分钟前
支付 GMV当前 ¥100,000 ／ 基线 ¥160,000
支付买家数1,000 ／ 1,500
直播渠道¥60,000 ／ ¥110,000
商城渠道¥40,000 ／ ¥50,000
经营健康度直播时长 库存 履约

生产环境中，这些字段由抖店、直播、投放及数仓的小时表提供。

② Agent 工作流

  1. 确认指标口径与基线，判断是否真的异常
  2. 拆解 GMV：买家数 × 件单数 × 客单价
  3. 按渠道、直播间、SKU 排序波动贡献
  4. 用供给、库存等证据核验根因假设
  5. 输出置信度、影响金额与运营动作

点击“播放”开始

Agent 不会一开始就猜原因。它先校验数据和异常幅度，再逐层收敛到可验证的根因。

③ Agent 执行日志

等待运行… > 输入：2 条小时级经营明细 > 策略：同星期同小时 / 昨日同小时基线

面试讲解话术

“我设计的重点不是一个静态 GMV 看板，而是一个可解释的诊断 Agent。它先量化异常，再做 GMV 因子分解，接着按业务维度计算贡献，最后用运营事实核验，而不是把相关性直接当成因果。”
