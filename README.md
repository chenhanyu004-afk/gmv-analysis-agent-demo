# GMV 诊断工作台 v2

[在线工作台](https://chenhanyu004-afk.github.io/gmv-analysis-agent-demo/)

基于输入数据实时计算的离线规则诊断原型。无预设根因，无播放式分析，无大模型调用。
GitHub Pages 使用根目录 index.html；app/demo.html 为同版页面。

## 使用
选择内置验证案例，或下载样本 JSON 后替换成自己的数据并导入。
设置相对变化与金额阈值，运行诊断；展开输入与计算方法查看依据，导出完整诊断凭据。
任何输入变更均需要重新运行，旧结果不能直接导出。

## 计算与证据
- GMV = 支付订单数 × 每单支付金额；不将跨 SKU 买家数相加。
- 对称分摊两个因子的变化，和严格等于总 GMV 变化。会显示对账残差。
- 渠道与 SKU 独立汇总；各维度内部对账，不跨维度累加。
- 缺货等事件需匹配对象、窗口和来源。事件仅支持关联假设，不能证明因果或量化该原因的损失。
- 输入需包含完整性、可比性、互斥归属声明及独立总盘。声明无法替代源系统核验。
- 负数、重复桶、总盘不符、不完整数据、超过15分钟的数据延迟均阻断分析。
- 时效相对于输入 as_of；历史快照不代表实时数据。
- 单一指定基线不是统计预测。未触发阈值不表示统计上正常。
- JSON 导入在浏览器本地处理，不发送输入数据到服务器。

## 适用性
适用于已整理为两期互斥「渠道 × SKU」桶的人民币支付GMV排查。
多SKU订单需统一唯一归属规则，不能把商品行数量当订单数。
目前支持缺货与开播时长事件；不支持自动拉取抖店、实时调度、自动投放调整或通用自然语言调查。
样本全部合成。尚无真实业务回测，因此不宣称误报率、召回率或诊断准确率达标。

## 验证
本次本地验证通过8组确定性检查（含100组数值分解对账）、场景切换、阈值更新、导出、桌面及390px页面显示。
测试证明实现的这些行为，不代表生产环境业务准确率。

## 旧版 API
app/analyzer.py 与 POST /analyze 是旧版原型，不是v2网页使用的引擎。
旧版存在口径和归因局限，请勿用其结果作生产决策；使用上方v2网页诊断。
真实业务接入前需将v2指标合同和校验规则接入后端，再做历史回测与人工验收。
